# نكست كامباين — Next Campaign

موقع مطبوعات وهدايا دعائية للشركات، وهدايا شخصية باسم صاحبها.
Next.js فوق Supabase، عربي RTL.

> **الحالة:** P0 → P4 خلصوا. الموقع شغّال من ناحية العميل (تصفّح، تخصيص،
> حساب تكلفة حي، رفع لوجو، إرسال طلب، تتبع) ومن ناحيتك (لوحة تحكم على
> `/admin`: الطلبات، آلة الحالات، أمر شغل للطباعة، إدارة المنتجات والأسعار
> والطباعة، الإعدادات، المستخدمين).
> الخطة الكاملة في `docs/الخطة.md`، وقرارات التصميم في `docs/القرارات.md`.
>
> **مش مبرمج؟** ابدأ من [`docs/ابدأ-من-هنا.md`](docs/ابدأ-من-هنا.md) — تشغيل
> الموقع على جهازك، التعديل عليه، ونشره على الإنترنت، خطوة بخطوة.

## ٢. تشغيل المشروع لأول مرة

الأدوات مش على PATH على الجهاز ده:
`node` في `G:\dev-tools\node\node.exe`.

```bash
npm install
```

تثبيت واحد من الجذر بيغطي `web/` و `tools/schema-check/` (npm workspaces).

### قاعدة البيانات

١. اعمل مشروع Supabase **جديد ومخصص للموقع ده لوحده**.
   قاعدة بيانات واحدة = تطبيق واحد — التصادم مع تطبيق تاني كلّفنا تلات أعطال
   صامتة في مشروع الاسكوتر.

٢. من لوحة Supabase → SQL Editor → New query → الصق محتوى
   `supabase/SETUP-ALL-IN-ONE.sql` كامل → Run.
   الملف آمن لو اتشغّل أكتر من مرة.

٣. ⚠ **Authentication → Sign In / Providers → Anonymous sign-ins → Enable.**
   خطوة إعداد في اللوحة مش في SQL، ومن غيرها رفع اللوجو بيفشل — العميل بيرفع
   من غير حساب، والملف بيتخزن تحت هوية مجهولة بتتعمل وقت الرفع، وسياسة
   التخزين بتقارن أول مقطع في المسار بالهوية دي.

٤. Project Settings → API → انسخ **Project URL** و **anon public key**.

٥. انسخ `web/.env.local.example` باسم `web/.env.local` وحط فيهم.

### التشغيل

```bash
npm run dev
```

الموقع على `http://localhost:3000`.

## ٣. معاينة من غير Supabase

عشان تشوف الكتالوج قبل ما تعمل مشروع Supabase أصلاً:

```bash
npm run preview:start
```

أمر واحد: بيبني بوستجرس مؤقت، بيطبّق الترحيلات والبذر الحقيقيين، بيبدّل طبقة
البيانات، وبيشغّل الموقع على `http://localhost:3000`. البيانات هي البذر الحقيقي
مش موك. ولو `web/.env.local` مش موجود بيعمله بقيم وهمية — من غيره الموقع بيعرض
شاشة «محتاج إعداد» لإنه بيتأكد من المفاتيح قبل ما يعرض أي حاجة.

`preview:dump` بيشغّل بوستجرس مؤقت، بيطبّق الترحيلات والبذر الحقيقيين، وبيكتب
`web/preview-data.json`. `preview:on` بيبدّل طبقة البيانات لتقرا الملف ده.
البيانات دي هي البذر الحقيقي مش موك.

**قبل أي commit أو نشر:**

```bash
npm run preview:off
```

`npm run preview` من غير لاحقة بيقولك انت في أنهي وضع.

## ٤. الفحوصات — لازم يبقوا نضاف قبل أي تسليم

```bash
npm run db:check
```
بيشغّل الترحيلات الحقيقية على بوستجرس مؤقت و**١٥٠ تأكيد**: كتالوج المواصفات،
سلّم الأسعار، محرك التسعير (٢٠٠ اختيار عشوائي SQL مقابل JavaScript بالقرش)،
آلة حالات الطلب، ملكية ملفات العملاء، حدود الـ RLS، وسطح الدوال اللي anon
بيقدر يوصله.

```bash
npm run typecheck
```

```bash
npm run build
```

```bash
npm run check:rtl
```
بيرفض أي خاصية CSS فيزيائية (`margin-left` وأخواتها). الخصائص المنطقية بس.

وواحد خامس بيحتاج السيرفر شغّال:

```bash
npm run check:routes
```
بيتأكد إن كل رابط في السايت ماب بيرد ٢٠٠، وإن كل صفحة منتج عليها `og:title` و
`og:description` و JSON-LD صالح. **معاينة الواتساب بتكسر بالسكوت** — الفحص ده
هو اللي بيمسكها.

## ٦. حاجات لازم تعرفها قبل ما تعدّل

### القاعدة: أي كود الهارنس بيقارنه بـ SQL بيتكتب JavaScript مش TypeScript
`web/lib/phone.js` و `arabic.js` و `money.js` و `pricing.js`.
الهارنس بيستورد الملفات دي **بالظبط** ويتأكد إنها بتدي نفس نتيجة
`normalize_phone()` و `fold_arabic()` و `price_quote()` في SQL. لو بقت `.ts`
الهارنس هيحتاج build step، وأول ما يترجم نسخته الخاصة يبقى بيختبر حاجة تانية
غير اللي الموقع بيشحنها. `checkJs` مفعّل فالـ JSDoc بيتفحص زي أي `.ts`،
وأنواع محرك التسعير عايشة في `pricing.types.ts` وبتتربط بـ JSDoc.

### التسعير متنفّذ مرتين، والاختبار هو اللي بيخليه مقبول
`price_quote()` في SQL هي **المرجع**. `computeQuote()` في `pricing.js` بتحسب
نفس الأرقام في المتصفح عشان الإجمالي يتحرك مع كل ضغطة من غير رحلة للسيرفر —
لكنها مقيّم غبي فوق البيانات اللي `quote_product()` بعتتها، مش قواعد تانية.
الهارنس بيعدّي **٢٠٠ اختيار عشوائي** على الاتنين ويقارن **بالقرش**.
**لو غيّرت الحسبة في ناحية، غيّرها في التانية في نفس الـ commit.**

### ترقيم الترحيلات
`20260810100006_rls.sql` بيسحب `execute` من `anon` على **كل** الدوال.
أي ملف جديد **لازم** يترتب بعده و**لازم** يحمل منحه بنفسه.
ملف بيترتب قبله بينشئ دالة بتتسحب صلاحيتها فوراً — وعلى قاعدة مثبّتة أصلاً ملف
الـ RLS مش بيتعاد تشغيله، فالعطل بيظهر بس على تثبيت جديد بعد شهور.
`npm run db:build` بيعدّ اللي بعده وبيقولك.

### القاعدة الصارمة: مفيش عمود خاص على جدول مقروء لـ anon
`products` و `categories` و `occasions` و `print_methods` و
`product_price_tiers` و `site_settings` كلها مقروءة للزوار.
**ممنوع** يتضاف عليها سعر تكلفة أو مورّد أو هامش أو ملاحظة داخلية —
دول يروحوا `product_private`.
الشغل ده كله هامش، فالقاعدة **هتتجرّب**. الهارنس بيفحص أسماء الأعمدة آلياً
ويكسّر البناء لو حد نساها.

### بعد أي تعديل تحت `supabase/`
```bash
npm run db:build
```
```bash
npm run db:check
```

### الفرز بـ `price_at_moq` مش `price_from`
`price_at_moq` هو سعر القطعة عند أقل كمية مسموح بيها — التكلفة الصادقة.
`price_from` أرخص شريحة. الفرز بالتانية بيعرض لعميل بيشتري ٥٠ سعر الألف قطعة.

### مفتاح `anon` موجود في كود المتصفح، وده طبيعي
مالوش صلاحيات من نفسه، والـ RLS هو البوابة، وكل كتابة هتعدّي على دالة
security-definer محدودة المعدل. **المفتاح اللي ممنوع يظهر في المشروع خالص هو
`service_role`.**

**الميزات بتظهر لما تشتغل، مش قبلها** — عشان كده زرار الواتساب في صفحة تأكيد
الطلب مش بيظهر أصلاً لو رقم الواتساب مش متسجّل في `site_settings`.

### ⚠ أول حاجة بعد التثبيت: غيّر كلمة سر المدير
التثبيت بيعمل حساب مدير `01000000000` بكلمة سر مكتوبة في
`supabase/migrations/20260810100011_accounts.sql`. الملف ده في المستودع، يعني
أي حد يقراه يعرفها. ادخل `/admin` → المستخدمين → غيّر كلمة السر.
